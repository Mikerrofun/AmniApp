## 1. Зачем

В форме создания шаблона API модель вводилась вручную как произвольная строка: пользователь должен был точно знать id модели (`gpt-4o-mini`, `claude-sonnet-4` и т.д.), опечатка или устаревшее имя обнаруживались только при первой отправке сообщения — ошибкой от провайдера. При этом у всех поддерживаемых провайдеров (OpenAI-совместимый `GET /models`) список моделей можно получить по тому же ключу, который пользователь уже ввёл. Фича — дропдаун выбора модели из реального списка провайдера с поиском. Модель нельзя ввести, пока не введён ключ: без ключа список моделей неоткуда получить, а модель без ключа — заведомо битый шаблон.

## 2. Архитектура: кто кого вызывает

Фича разложена на три слоя; зависимости идут только сверху вниз, общение с UI — через zustand-стор.

```
TemplateForm.tsx  (рендер полей, onBlur поля ключа)
  └── useTemplateForm.ts  (логика формы: триггеры запроса, сбросы, валидация)
        ├── apiTemplateFormSchema        (zod, точка валидации формы)
        ├── useModelsStore.ensureModels / cancelKey   (запрос + кэш + аборт)
        └── showToast / useT             (ошибки, i18n)

ModelSelect.tsx  (чистый рендер по status)
  └── useModelSelect.ts  (состояние открыт/закрыт, поиск, чтение кэша)
        ├── useModelsStore               (тот же стор — единственный мост
        │                                 между формой и селектом)
        └── filterModels                 (чистая функция поиска)

useModelsStore (zustand, shared/lib/ai)
  └── fetchAvailableModels  (models.ts: expo/fetch, Bearer, таймаут)
        └── normalizeModelList  (normalize-models.ts: чистая нормализация)
```

Файлы фичи:

| Файл | Роль |
| --- | --- |
| `shared/lib/ai/models.types.ts` | Типы результата запроса и статусов записи кэша |
| `shared/lib/ai/models.config.ts` | Таймаут и дебаунс |
| `shared/lib/ai/models.ts` | `fetchAvailableModels` — единственная точка сети |
| `shared/lib/ai/normalize-models.ts` | `normalizeModelList` — чистая функция |
| `shared/lib/ai/models-store.ts` | `useModelsStore` — кэш, дедупликация, аборт |
| `shared/components/ModelSelect/*` | `ModelSelect` + `useModelSelect` + конфиг + `filterModels` |
| `app/(tabs)/api/components/TemplateForm/*` | Форма: `useTemplateForm` — триггеры и сбросы |
| `schemas/api-template.ts` | `apiTemplateFormSchema` — валидация при сохранении |

Форма и селект не знают друг о друге: `useTemplateForm` пишет в стор (`ensureModels`/`cancelKey`), `ModelSelect` читает из стора. Единственная связка — оба работают с ключом `modelsCacheKey(provider, apiKey)`.

## 3. Где/что уже было

Задача была не писать новое, а собрать фичу из уже готовых кусков:

- **`openai-compat-client.ts`** — паттерн запроса к провайдеру с устройства: нативный `expo/fetch`, `Authorization: Bearer`, без бекенда. Клиент моделей повторяет паттерн, но не переиспользует сам клиент (тот заточен под chat completions со стримингом).
- **`API_TEMPLATE_PRESETS`** (`types/api-template.ts`) — пресеты провайдеров уже содержат `baseUrl`, из которого строится `GET {baseUrl}/models`. Новый код не добавляет ни одного нового URL.
- **Паттерн zustand-стора с in-memory кэшем** — как в `search-store.ts`/`templates-store.ts`: стор держит только сериализуемое состояние, AbortController живут рядом в модуле.
- **`showToast`** (`shared/components/ui/Toast`) и **`useT`** (i18n) — существующие механизмы ошибок и локализации.

## 4. Реализация

### 4.1 Сеть: `models.ts` — `fetchAvailableModels({ baseUrl, apiKey, signal })`

- Принимает: baseUrl провайдера, ключ, опциональный внешний `AbortSignal`.
- Возвращает: `{ ok: true, models: string[] } | { ok: false, reason: 'network' | 'unauthorized' | 'other' }` — ошибки классифицируются в результат, наверх ничего не выбрасывается.
- Один `AbortController` совмещает внешний сигнал и таймаут `MODELS_REQUEST_TIMEOUT_MS = 15000`: внешний abort прокидывается в контроллер, таймаут абортит тот же контроллер. Аборт — не сетевая ошибка (`TypeError`), поэтому различается по `controller.signal.aborted`.
- `401/403` → `unauthorized`, `TypeError` без аборта → `network`, остальное → `other`.

### 4.2 Нормализация: `normalize-models.ts` — `normalizeModelList(payload)`

- Принимает: распарсенный JSON ответа провайдера (типизирован как `unknown`).
- Возвращает: отсортированный массив уникальных id (`data[].id`, только непустые строки, trim, dedup через `Set`, `localeCompare`).
- Вынесена в отдельный файл от клиента сознательно: `models.ts` тянет `expo/fetch`, который недоступен в node-тестах, а нормализация — чистая функция.

### 4.3 Кэш: `models-store.ts` — `useModelsStore`

Ключ записи — `modelsCacheKey(provider, apiKey)` = `"{provider}|{apiKey}"`: у разных провайдеров и разных ключей списки разные.

**Как пишется статус.** `ensureModels(provider, baseUrl, apiKey)`:

1. Запись уже `ready` или `loading` → выход (дедупликация параллельных вызовов; повторный вызов с тем же ключом — no-op).
2. Иначе создаётся `AbortController`, кладётся в карту `inFlightControllers`, запись ставится в `loading`.
3. После `await fetchAvailableModels(...)` — защита от гонки: если в карте уже другой контроллер (ключ сбросили/заменили, пока запрос был в полёте), ответ выбрасывается, состояние не трогается.
4. Иначе запись получает `ready` + models или `error`.

**Как чистятся данные.** `cancelKey(provider, apiKey)`: абортит in-flight запрос по ключу и удаляет запись из кэша. Вызывается формой при реальной смене ключа — частичные ключи («sk-ab…») мусор в кэше не задерживаются. При успехе сохранения формы поля просто очищаются — записи кэша остаются жить до рестарта приложения (in-memory на сессию, ничего не персистится: список моделей — дешёвый запрос, а не секрет).

### 4.4 Константы: `models.config.ts`

```ts
MODELS_REQUEST_TIMEOUT_MS = 15000  // таймаут GET /models
MODELS_FETCH_DEBOUNCE_MS  = 1000   // пауза после остановки ручного ввода ключа
```

Минимальной длины ключа нет: ключи провайдеров бывают очень короткие, длина ничего не говорит о валидности. Единственное условие запроса — непустой ключ.

### 4.5 Триггеры запроса: `useTemplateForm.ts`

Список моделей запрашивается тремя путями, условие одно — непустой ключ:

1. **Вставка из буфера** — сразу. React Native не даёт события paste, поэтому вставка детектится скачком длины: `text.length - prev.length > 1` (при `autoCorrect={false}` ручной ввод вставляет по символу). Эффект хранит прошлое значение в `prevKeyRef`.
2. **Ручной ввод** — через `MODELS_FETCH_DEBOUNCE_MS` (1с) после последнего символа; каждый новый ввод сбрасывает таймер.
3. **Потеря фокуса поля ключа** (`handleApiKeyBlur`, `onBlur` у `TextInput`) — сразу, не дожидаясь паузы. `ensureModels` идемпотентна, двойной вызов с дебаунсом безопасен.

**Сбросы при смене входа:**

- Смена ключа (`setApiKey`): модель сбрасывается в `""` (у нового ключа список другой) + `cancelKey` старого ключа (аборт in-flight + чистка мусорной записи).
- Смена провайдера (`changeProvider`): модель сбрасывается в `""`. Кэш старого провайдера **не** чистится — запись `provider|key` валидна, пользователь может вернуть провайдер обратно, и список возьмётся из кэша без запроса.

**Сохранение** (`handleAdd`): `apiTemplateFormSchema.safeParse` — при ошибке общий тост `apiTab.invalidForm`; при успехе `addTemplate`, поля очищаются; отказ вставки `UNIQUE(name)` → тост `duplicateName`, остальное → `saveFailed`.

### 4.6 Схема: `apiTemplateFormSchema`

Плоский `z.object` — `name/provider/model/apiKey`, все поля обязательны (`min(1)`). Кросс-полного правила «модель требует ключ» в схеме нет и не нужно: UI не даёт выбрать модель без ключа (см. 4.7), а при смене ключа модель сбрасывается — состояние «модель без ключа» недостижимо.

### 4.7 UI: `ModelSelect` — машина состояний поля

`ModelSelect.tsx` — чистый рендер, вся логика в `useModelSelect.ts` (открыт/закрыт, поисковый запрос, чтение записи стора, производные флаги). Константы (`MODEL_LIST_MAX_HEIGHT`, `FIELD_CLASS`, `EMPTY_MODELS`) — в `ModelSelect.config.ts`.

Поле выбирает, что показать, по `status` записи кэша:

| status | Условие | Что на экране |
| --- | --- | --- |
| `idle` | ключа нет (или запрос ещё не стартовал) | Заблокированный `TextInput` с подсказкой «Вставьте ключ, чтобы загрузить модели» (`modelSelect.insertKeyHint`) |
| `loading` | запрос в полёте | Строка со спиннером «Загрузка моделей...» |
| `ready`, models > 0 | список получен | Кнопка с текущей моделью и шевроном → `Modal`-дропдаун с поиском |
| `error` или `ready`, models = 0 | провайдер не отдал список | Обычный `TextInput` ручного ввода имени |

Дропдаун: `filterModels` (case-insensitive подстрока), `FlatList` с виртуализацией (`MODEL_LIST_MAX_HEIGHT`), выбранная модель подсвечена `bg-accent`, тап вне карточки закрывает. Дропдаун не открывается при `disabled` или пустом ключе (`isDropdownLocked`, opacity-50).

Ручной ввод разрешён **только** в последней строке таблицы — это единственный сценарий, где список получить не удалось. Пока ключа нет, ввести модель текстом нельзя: в этом смысл паттерна.

```tsx
// src/app/(tabs)/api/components/TemplateForm/TemplateForm.tsx
<ModelSelect
  baseUrl={API_TEMPLATE_PRESETS[provider].baseUrl}
  provider={provider}
  apiKey={apiKey}
  value={model}
  onChange={setModel}
/>
```

## 5. Потоки данных

**Вставка ключа → дропдаун:**

```
Вставка ключа в TextInput (onChange)
  ↓
setApiKey(text): модель → "", cancelKey(старый ключ)
  ↓
useEffect [apiKey, provider]: скачок длины > 1 → задержка 0
  ↓
ensureModels(provider, baseUrl, apiKey)
  ├── запись ready/loading → выход (кэш/дедуп)
  └── loading → fetchAvailableModels (GET {baseUrl}/models, Bearer, 15s)
        ↓ normalizeModelList → string[]
  ↓ (контроллер ещё актуален?)
entries[key] = { status: 'ready', models }
  ↓
ModelSelect: idle → ready, заблокированное поле → дропдаун
```

**Смена ключа на другой:**

```
setApiKey(новый) → setModel("") + cancelKey(старый)
  ↓
cancelKey: abort() in-flight → запись старого ключа удалена из кэша
  ↓
(вставка/пауза/blur) → ensureModels(новый ключ) → loading → ready/error
```

**Ошибка списка (жизненный цикл):**

```
fetchAvailableModels → { ok: false, reason }
  ↓
entries[key] = { status: 'error', models: [] }
  ↓
ModelSelect: error → ручной ввод имени модели
  ↓
Повторный запрос того же ключа НЕ перезапишет ошибку (ensureModels
видит запись и выходит) — но запись чистится cancelKey'ем при первой
же правке ключа, и следующий запрос пойдёт снова
```

## 6. Проверки: что и где валидируется

| Проверка | Где | Когда |
| --- | --- | --- |
| Ключ непустой | `useTemplateForm` (эффект, blur) | перед каждым авто-запросом списка |
| Дедупликация запросов | `ensureModels` | каждый вызов |
| Актуальность ответа (гонки) | `ensureModels`, после `await` | каждый ответ |
| Форма: все поля `min(1)`, провайдер из enum | `apiTemplateFormSchema.safeParse` | только при сохранении |
| Дропдаун заблокирован без ключа | `useModelSelect.isDropdownLocked` | каждый рендер |
| Ручной ввод только при error/пустом списке | `ModelSelect` по `status` | каждый рендер |

Тесты (`tests/api-templates/`, `pnpm test`): `normalizeModelList` (извлечение/trim/dedup/сортировка/мусор), `apiTemplateFormSchema` (валидная форма, короткий ключ, пустые поля, неизвестный провайдер), `filterModels` (поиск).

## 7. Почему так, а не иначе

1. **Стор-кэш, а не состояние в хуке формы.** Список моделей зависит от пары (провайдер, ключ) и нужен в двух местах — форма триггерит, селект читает. Стор переживает размонтирование формы, а `ensureModels` с дедупликацией делает вызов из любого места безопасным.

2. **Ошибки результатом, а не исключением.** `unauthorized` (невалидный ключ — нормальный сценарий ввода) и `network` (нет сети) — ожидаемые исходы, а не аварии. Классификация в `FetchModelsResult` позволяет UI молча деградировать в ручной ввод, не завязываясь на тексты исключений.

3. **Деградация в TextInput только при ошибке/пустом списке.** Если провайдер не отдал список, форма всё равно должна работать как раньше — ручной ввод. Но пока ключа нет, ввод заблокирован: модель без ключа — битый шаблон, и честнее показать подсказку, чем позволить сохранить поломку.

4. **Детект вставки скачком длины.** В RN нет события paste; при `autoCorrect={false}` ручной ввод даёт +1 символ за раз, вставка — больше. Эвристика простая и ложные срабатывания не страшны: «вставка» лишь отменяет задержку debounce.

5. **`normalizeModelList` отдельным файлом.** `models.ts` импортирует `expo/fetch` и не запускается в node-тестах; чистая нормализация вынесена, чтобы тестировать её без эмуляции Expo.
