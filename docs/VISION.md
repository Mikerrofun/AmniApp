# AmniApp — Vision

> Универсальный приватный AI-чат клиент: подключаешь свои API-ключи, общаешься с любыми моделями, все данные остаются на твоём устройстве.

---

## Философия проекта

**Privacy First.** Все данные (история чатов, API-ключи, настройки) хранятся локально на устройстве. Никаких облачных серверов, никакой аналитики, никакой передачи данных третьим лицам. Приложение — лишь клиент между тобой и AI-провайдерами, использующий твои ключи.

**Bring Your Own Key (BYOK).** Не привязываемся к конкретному провайдеру или модели — пользователь сам выбирает, с кем работать. Поддержка любых OpenAI-совместимых API из коробки (OpenAI, OpenRouter, DeepSeek, Groq, Ollama, и т.п.).

**Local-First Architecture.** SQLite для данных, SecureStore для ключей, expo-sqlite для полнотекстового поиска и векторного поиска. Работает оффлайн, синхронизация опциональна и всегда под контролем пользователя.

## Целевая аудитория

### Основные группы пользователей:

1. **Разработчики и Tech-Savvy юзеры**
   - Экспериментируют с разными моделями и провайдерами
   - Хотят контроль над своими данными и API-ключами
   - Нужна гибкость в выборе моделей под разные задачи

2. **Privacy-Conscious пользователи**
   - Не доверяют облачным сервисам с историей чатов
   - Хотят использовать AI без компромиссов по приватности
   - Готовы платить провайдерам напрямую за прозрачность

3. **Пользователи в регионах с ограничениями**
   - Доступ к AI-сервисам через proxy/VPN
   - Используют OpenRouter или локальные модели (Ollama)
   - Нужна автономная работа без зависимости от инфраструктуры

## Ключевые use cases

- **Экспериментирование**: Быстрое переключение между моделями (GPT-4, Claude, DeepSeek) для сравнения ответов на один запрос
- **Специализация**: Разные шаблоны для разных задач (кодинг на DeepSeek, креатив на Claude, быстрые запросы на Gemini Flash)
- **Приватность**: Чувствительные диалоги (бизнес, медицина, персональное) без утечки в облачные базы чат-сервисов
- **Оффлайн + локальные модели**: Ollama на домашнем сервере или M-чипе Mac, полная автономность
- **Cost optimization**: Гибкий выбор провайдера с лучшими ценами под задачу (OpenRouter agregator)

## Стек (технический фундамент)

- **React Native + Expo SDK 57** — кросс-платформа (iOS/Android), file-based routing (expo-router)
- **TypeScript (strict)** — типобезопасность на всех уровнях
- **NativeWind (Tailwind 3)** — utility-first стилизация
- **Zustand** — лёгкий state management без boilerplate
- **Zod** — runtime валидация схем (API responses, форм, конфигов)
- **expo-secure-store** — зашифрованное хранение API-ключей (Keychain на iOS, EncryptedSharedPreferences на Android)
- **expo-sqlite** — локальная БД с FTS5 (полнотекстовый поиск) и sqlite-vec (векторный поиск)
- **React Native Reanimated** — 60fps анимации на UI-потоке
- **Feature-Sliced Design (FSD)** — масштабируемая архитектура с чёткими границами слоёв

## Архитектура данных

### Гибридное хранение (разделение по типу данных):

| Тип данных               | Хранилище                   | Обоснование                                          |
| ------------------------ | --------------------------- | ---------------------------------------------------- |
| API-ключи                | `SecureStore`               | Зашифровано на уровне ОС, не попадает в бэкапы       |
| История чатов, сообщения | `SQLite`                    | Реляционная модель, FTS5 для поиска, быстрые запросы |
| Эмбеддинги для поиска    | `sqlite-vec`                | Векторная таблица для семантического поиска (KNN)    |
| Черновики, UI-стейт      | `Zustand` (memory)          | Сессионное состояние, стирается при рестарте         |
| Настройки приложения     | `SQLite` или `AsyncStorage` | Персистентные, но не критичные                       |

### Миграции схемы:

Версионирование через `PRAGMA user_version`, идемпотентные миграции (можно повторно запускать без ошибок), каждая фича может добавлять свою версию схемы.

### Синхронизация (roadmap v2+):

- Экспорт/импорт чатов в сжатом формате (JSON.gz или SQLite-дамп)
- Опциональная синхронизация через self-hosted бэкенд (WebDAV, S3-compatible, или P2P)
- **Важно**: синхронизация всегда opt-in и под контролем пользователя

## Структура приложения

### Нижняя навигация (3 вкладки):

#### 1. **Чат (главная)**

- Основной экран для общения с AI (streaming responses токен-за-токеном)
- Сайдбар слева — история чатов с гибридным поиском:
  - **Keyword-поиск** (FTS5) — по названию и контенту, мгновенно
  - **Semantic-поиск** (embeddings) — по смыслу, с debounce
  - Подсветка совпадений, группировка по датам
- Временный чат — режим "черновика" без сохранения до первой отправки
- Выбор шаблона (модели) — popover внизу, быстрое переключение между настроенными API
- Черновики текста — в памяти (sessionStorage-аналог), переживают переключение чатов, но не рестарт

#### 2. **API / Шаблоны**

- CRUD шаблонов: создать, редактировать, удалить, включить/отключить
- **Шаблон** = провайдер (preset: OpenAI, OpenRouter, custom base URL) + API-ключ + модель + параметры (temperature, system prompt, max tokens)
- Добавление шаблона:
  1. Выбор пресета провайдера или ввод custom base URL
  2. Ввод API-ключа → опциональный FastCheck
  3. Выбор модели из списка (если FastCheck успешен) или ввод вручную
  4. Настройка параметров (опционально)
  5. Сохранение → ключ в SecureStore, метаданные в SQLite
- Группировка шаблонов по провайдерам (визуальная)
- Быстрое включение/отключение без удаления

#### 3. **FastCheck**

- Standalone-вкладка для быстрой проверки ключа без создания шаблона
- Три последовательные проверки:
  1. **Валидность ключа** — простой запрос к `/models` или `/chat/completions`
  2. **Список доступных моделей** — парсинг `/models` для автозаполнения
  3. **Streaming работает** — тестовое сообщение со стримингом, проверка SSE
- Отчёт по каждой проверке (✓ / ✗ с описанием ошибки)
- Также используется внутри флоу создания шаблона (опционально)

### Настройки (верхняя кнопка):

- Тема (dark/light — пока только dark)
- Язык интерфейса (ru/en, автоопределение, выбор вручную)
- Шрифт (размер, семейство — опционально)
- Экспорт/импорт данных (roadmap)
- «Об авторе» + версия приложения

## Ключевые технические решения (и почему именно так)

### 1. **SQLite локально, а не облачная БД**

**Почему:**

- Приватность — данные не покидают устройство без явного экспорта
- Оффлайн-работа — не зависим от сети для открытия истории
- Производительность — нет network latency, мгновенный поиск (FTS5 + векторные индексы)
- Простота — не нужен backend, авторизация, синхронизация (пока)

**Trade-off:** Синхронизация между устройствами сложнее (но решаема экспортом или self-hosted sync).

### 2. **SecureStore для ключей, а не SQLite**

**Почему:**

- SQLite-файл попадает в device backups (iCloud, Google Drive) — ключи утекли бы туда
- SecureStore = OS-level encryption (Keychain на iOS, EncryptedSharedPreferences на Android)
- Ключи не живут в памяти приложения (читаются только при отправке запроса)

**Trade-off:** Ключи не синхронизируются между устройствами (это фича, не баг — безопасность > удобство).

### 3. **Context/Notes модель вместо Messages**

**Почему:**

- `context` (денормализованный текст чата) нужен для поиска и эмбеддингов
- `notes` (отдельные сообщения с ролями) нужны для отображения истории и запросов к API
- Разделение избавляет от пересборки контекста на каждый поиск и эмбеддинг
- FTS5-триггеры автоматически обновляют индекс при изменении `context`

**Trade-off:** Дублирование данных (messages → context), но выигрыш в производительности поиска огромный.

### 4. **Feature-Sliced Design (FSD)**

**Почему:**

- Масштабируемость — каждая фича (chats, api-templates, search) изолирована
- Публичный API фичи через `index.ts` — внутренности скрыты
- Слои (app → features → shared → lib) дают чёткие boundaries
- Легко тестировать и рефакторить отдельные фичи

**Trade-off:** Больше файлов и структуры, но в долгосроке это окупается поддерживаемостью.

### 5. **Zustand вместо Redux/MobX**

**Почему:**

- Минимальный boilerplate — стор = одна функция с set/get
- Селекторы из коробки, оптимизация ре-рендеров через `useStore(state => state.field)`
- Не требует Provider-обёртки
- TypeScript-friendly без дополнительных либ

**Trade-off:** Нет middleware-экосистемы Redux (но для нашего use case не нужна).

### 6. **Streaming через fetch + SSE, а не SDK**

**Почему:**

- `expo/fetch` даёт нативный streaming в React Native (без polyfill)
- Ручной парсинг `data: <json>` + `[DONE]` тривиален
- Не зависим от OpenAI SDK (который может не поддерживать нужный провайдер)
- Zod-валидация chunks даёт устойчивость к мусорным данным в потоке

**Trade-off:** Пишем парсер вручную, но контроль полный и ошибки предсказуемы.

## Открытые вопросы и решения по ходу

### Context Management (v1.1)

- Стратегия с длинными диалогами: автоматическое усечение старых сообщений при превышении token limit (настройка per шаблон)
- Суммаризация контекста: опционально, через вызов LLM (summarize last N messages)
- Ручная очистка: кнопка "Clear context" в меню чата (удаляет notes, оставляет чат в истории)

### Синхронизация (v2.0)

- Формат: SQLite dump (схема без ключей) или структурированный JSON
- Сжатие: gzip/brotli для экономии трафика
- Транспорт: WebDAV (стандарт) или REST API (самописный backend)
- Конфликты: timestamp-based merge, UI для ручного разрешения конфликтов
- Self-hosted: Docker-образ с минимальным backend (REST + auth + storage)

### Multi-modal (v1.5)

- Attachments: через `expo-image-picker`, base64-encoding для API
- Preview: `<Image>` inline в чате, lightbox при клике
- Models: проверка capabilities провайдера перед отправкой (не все поддерживают vision)

### Advanced Features (v2.5)

- Side-by-side comparison: split-screen layout, параллельные запросы через Promise.all
- Fork conversation: tree structure в БД (parent_id для messages), UI навигации по веткам
- Function calling: JSON schema editor, sandbox для execution (WebView или jsdom)

## Принципы разработки

1. **Privacy by Design** — каждая фича проектируется с учётом приватности (данные локально, минимум внешних запросов)
2. **Graceful Degradation** — отсутствие ключа/сети/фичи не ломает приложение (keyword-поиск работает без embeddings, чат работает без синхронизации)
3. **Type Safety** — TypeScript strict mode, Zod для runtime validation, никаких `any`
4. **Mobile-First UX** — оптимизация под тач, клавиатура не перекрывает ввод, safe area handling
5. **Open Source Spirit** — даже если проект закрытый, архитектура должна допускать self-hosting и форки

## Non-Goals (что сознательно НЕ делаем)

- ❌ Встроенный магазин моделей или подписки — только BYOK
- ❌ Облачный backend по умолчанию — только self-hosted опция
- ❌ Аналитика и телеметрия — никаких трекеров, даже анонимных
- ❌ Социальные фичи (sharing, публичные чаты) — приватность превыше всего
- ❌ Web-версия как primary platform — фокус на native mobile experience
- ❌ Vendor lock-in — всегда возможность экспорта данных в открытом формате
