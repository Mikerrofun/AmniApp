# Temporary chat — follow-up итерация

Дата: 2026-10-15
Ветка: `TemporaryChat`
Связано: `docs/feature/temporaryChat.md` (полное описание фичи)

## Что сделали в этой итерации (кратко)

1. **Эмбединг названия — только при rename.** Убрали генерацию `title_embedding` при создании чата. Теперь эмбединг пишется единственной точкой — `handleRename` в `use-chat-actions.ts` (`renameChat` → `updateTitleEmbedding`).
2. **Guard на неизменённое название.** В `ChatPopoverRename`: если текст после trim совпадает с текущим названием, Save просто закрывает popover — ни title, ни эмбединг не перезаписываются. Раньше сохранение дефолтного «New chat» как есть проходило как rename и записывало бесполезный эмбединг.
3. **Формализация временного чата.** В сторе появились `focusInputToken` + `requestInputFocus()` (фокус поля ввода временного чата) и `pendingRenameChatId` + `consumePendingRename(id)` (авто-rename нового чата).
4. **Кнопка временного чата** (`TempChatButton`) справа от триггера панели: переключает чат, фокусит ввод, закрывает панель (кроме десктопа), лёгкий haptic (`expo-haptics`, guard на web). Повторное нажатие во временном чате — no-op с тостом «Already in a new chat» (см. п. 8).
5. **Cross-fade переход** в `ChatContent` при смене активного чата (чат ↔ временный и чат ↔ чат): старый слой `FadeOut` 150ms, новый `FadeInDown` 200ms с задержкой 80ms, слои absolute — перекрываются, а не выталкиваются.
6. **Размеры кнопок:** триггер панели и кнопка временного чата увеличены с 30 до 38 (зеркальная пара, +8px); иконка внутри кнопки временного чата — 16px (24 занимала всю ширину кружка, 18 — промежуточный вариант).
7. **Гигиена стора:** `deleteChat` гасит `pendingRenameChatId`, если удалили чат, на который висел сигнал.
8. **Универсальный тост** (`src/shared/components/ui/Toast/`): zustand-стор + `showToast(text)` — вызывается откуда угодно без пробросов пропсов; `Toast.tsx` — серый скруглённый контейнер (`bg-neutral-800/95`, `rounded-xl`), белый текст, по центру экрана, `pointerEvents="none"`, fade-in/out через reanimated, автоскрытие 2s (таймер перезапускается при повторном вызове), `toastKey` инкрементится на каждый вызов (перезапуск анимации для одинакового текста). Смонтирован один раз в `chat.tsx`.

## Основной флоу temporaryChat (простыми словами)

Временный чат — это состояние «ничего не выбрано» (`activeChatId === null`). Текст, который ты печатаешь, живёт в `globalDraft` стора. Настоящий чат создаётся только при первой отправке сообщения: `createChat()` пишет в БД, делает чат активным и **стирает** `globalDraft` — вернуться к временному чату после этого нельзя.

Кнопка временного чата:
- если мы в обычном чате — переключает `activeChatId` в `null` (текст обычного чата остаётся в его собственном драфте, не теряется), затем haptic → `requestInputFocus()` → закрытие панели;
- если мы уже во временном чате — **ничего не делает**, только показывает тост «Вы уже в новом чате». Драфт и фокус намеренно не трогаются: раньше эта ветка стирала `globalDraft` (можно было потерять набранный текст) и была источником ошибки при повторном нажатии.

## Как прокидывается ключ авто-rename (простыми словами)

Проблема: после нажатия «Новый чат» новый элемент списка появляется в `FlatList` **не мгновенно** — он приезжает из БД асинхронно. Если бы «открой rename» хранилось в локальном состоянии компонента, его было бы некому выставить — компонента ещё не существует.

Решение — сигнал в глобальном сторе:

1. `createChat()` после создания пишет в стор `pendingRenameChatId = <id нового чата>`. Сигнал просто лежит там и ждёт.
2. Каждый `ChatListItem` (элемент списка) при рендере сравнивает: **мой id совпадает с сигналом?** Совпадает только у одного элемента — у нового чата. Когда он наконец смонтируется, первое же сравнение даёт «да» → его popover рендерится сразу открытым в режиме rename. Никаких эффектов и таймеров — чистое производное состояние.
3. Пользователь печатает название и жмёт Save (или Cancel, или тапает вне). В любом из этих случаев popover закрывается, и элемент вызывает `consumePendingRename(id)` — сигнал стирается из стора. Заодно дёргается `onRenameComplete` → панель сайдбара закрывается.
4. Обычный rename через меню dots идёт мимо этого механизма: сигнал не выставляется и панель не закрывается.

Ключевая идея: **сигнал адресный и переживает рендер списка** — он «догоняет» элемент, который появился позже самого сигнала.
